\section{\texorpdfstring{\emph{Abstract}}{Abstract}}\label{abstract}

This specification defines three Verifiable Random Function with
Additional Data (VRF-AD) schemes -- Tiny VRF, Thin VRF, and Pedersen VRF
-- built on a transcript-based Fiat-Shamir transform with support for
multiple input/output pairs via delinearization. Tiny VRF and Thin VRF
are loosely inspired by IETF ECVRF
\href{https://datatracker.ietf.org/doc/rfc9381}{RFC-9381} {[}1{]},
adapted with a transcript-based Fiat-Shamir transform, support for
additional data, and multiple I/O pairs via delinearization. Pedersen
VRF follows the construction introduced by
\href{https://eprint.iacr.org/2023/002}{BCHSV23} {[}2{]} and serves as a
building block for anonymized ring signatures based on the ring proof
scheme derived from \href{https://eprint.iacr.org/2022/1205}{CSSV22}
{[}3{]}. All schemes are instantiated over the Bandersnatch elliptic
curve, constructed over the BLS12-381 scalar field as specified in
\href{https://eprint.iacr.org/2021/1152}{MSZ21} {[}4{]}.

\section{1. Preliminaries}\label{preliminaries}

\subsection{1.1. Groups and Fields}\label{groups-and-fields}

\begin{itemize}
\tightlist
\item
  \(\bold{G}\): Bandersnatch curve cyclic group of prime order \(r\),
  defined over the base field of prime order \(q\).
\item
  \(\bold{F}\): Scalar field of prime order \(r\)
  (i.e.~\(\mathbb{Z}_r\)).
\item
  \(\bold{\Sigma}^k\): Octet strings with length \(k \in \mathbb{N}\)
  (\(*\) for arbitrary length).
\item
  \(\mathcal{O}\): Identity point of \(\bold{G}\).
\end{itemize}

The EC group \(\bold{G}\) is the prime subgroup of the Bandersnatch
elliptic curve, in Twisted Edwards form, with finite field and curve
parameters as specified in
\href{https://eprint.iacr.org/2021/1152}{MSZ21} {[}4{]}. For this group,
\texttt{fLen} = \texttt{qLen} = \(32\) and \texttt{cofactor} = \(4\).

All point arithmetic MUST be performed in \(\bold{G}\). Points not in
\(\bold{G}\) MUST be rejected at all entry points; accepting a point on
the full curve but outside the prime-order subgroup enables
small-subgroup attacks that break the VRF relation.

\begin{itemize}

\item

\end{itemize}

\subsection{1.3. VRF-AD}\label{vrf-ad}

Regardless of the specific scheme, a \emph{Verifiable Random Function
with Additional Data (VRF-AD)} can be concisely represented by three
primary functions:

\textbf{Abstract interface}:

\begin{itemize}
\tightlist
\item
  \(\texttt{prove}(x \in \bold{F}, \overline{io} \in (\bold{G}\times \bold{G})^n, ad \in \bold{\Sigma}^*) \to \Pi\)
\item
  \(\texttt{verify}(Y \in \bold{G}, \overline{io} \in (\bold{G}\times \bold{G})^n, ad \in \bold{\Sigma}^*, \Pi) \to (\top \mid \bot)\)
\item
  \(\texttt{output}(O \in \bold{G}) \to o \in \bold{\Sigma}^N\)
\end{itemize}

For Pedersen VRF (section 4), the public key \(Y\) is not an explicit
input to \(\texttt{verify}\); the proof \(\Pi\) carries a blinded
commitment \(\bar{Y}\) instead.

The additional data \(ad\) is an arbitrary-length octet-string signed
together with the VRF output. It does not influence the produced VRF
output. The length of \(ad\) MUST NOT exceed \(2^{64} - 1\) bytes, as
the length is encoded via \(\texttt{enc\_64}\) in the VRF transcript
(section 1.6.5).

\subsection{1.4. Constants}\label{constants}

\begin{itemize}
\item
  \texttt{suite\_id} = \texttt{"Bandersnatch-SHA512-ELL2-v1"} --- the
  27-byte ASCII string identifying the cipher suite. It bundles several
  tightly-coupled choices: curve (Bandersnatch in Twisted Edwards form),
  transcript construction (HashTranscript over SHA-512), nonce algorithm
  (RFC-8032 inspired), challenge derivation (transcript squeeze), point
  encoding (compressed little-endian), hash-to-curve (Elligator 2 random
  oracle), and security level (128-bit). Bump the trailing version
  suffix when any of these changes. Version 2 of this suite,
  \texttt{"Bandersnatch-SHA512-ELL2-v2"}, differs only in the
  \(Z_{pad}\) prefix of hash-to-curve (Appendix A.2), which follows
  \href{https://datatracker.ietf.org/doc/rfc9380}{RFC-9380} exactly. The
  reference implementation provides it as \texttt{bandersnatch\_v2}. It
  may replace this version in a future draft.
\item
  \texttt{challenge\_len} = 16 bytes (128-bit security).
\item
  \texttt{expanded\_scalar\_len} =
  \(\lceil(\lceil\log_2(r)\rceil + 128) / 8\rceil\) = 48 bytes.
\end{itemize}

\subsection{1.5. Codec}\label{codec}

\begin{itemize}
\tightlist
\item
  \(\texttt{enc\_scalar}(s \in \bold{F})\): Encodes a scalar into 32
  octets in little-endian representation.
\item
  \(\texttt{dec\_scalar}(buf \in \bold{\Sigma}^{32})\): Interpret octet
  string \(buf\) as a little-endian integer. MUST output ``INVALID'' if
  the resulting value is \(\geq r\).
\item
  \(\texttt{enc\_point}(P \in \bold{G})\): Encodes a point in compressed
  form. The \(y\) coordinate is serialized in little-endian and the most
  significant bit of the last octet encodes the sign of the
  \(x\)-coordinate. This gives \texttt{ptLen} = \texttt{fLen} = \(32\).
\item
  \(\texttt{dec\_point}(buf \in \bold{\Sigma}^{32})\): Interpret octet
  string \(buf\) as a compressed point. Mask the sign bit from the last
  octet and interpret the result as a little-endian integer. MUST output
  ``INVALID'' if the resulting value is \(\geq q\). Otherwise,
  decompress the point and MUST output ``INVALID'' if it does not decode
  to a point on the prime subgroup \(\bold{G}\).
\item
  \(\texttt{dec\_scalar\_mod}(buf \in \bold{\Sigma}^*)\): Interpret
  octet string \(buf\) as a little-endian integer and reduce modulo the
  prime field order \(r\).
\item
  \(\texttt{enc\_64}(n \in \mathbb{N}_{2^{64}})\): Encode integer \(n\)
  as an 8-byte little-endian octet string.
\end{itemize}

Aggregate types (e.g.~proofs) MUST be encoded as the concatenation of
their individual fields in the order given by the structure definition,
without any separator.

\subsection{1.6. Procedures}\label{procedures}

\subsubsection{1.6.1. Transcript}\label{transcript}

The transcript provides a Fiat-Shamir transform with an absorb/squeeze
interface. Data is absorbed into an internal hash state; output bytes
are squeezed from it. After the first squeeze, \(\texttt{absorb}\) MUST
NOT be called.

\textbf{Abstract interface}:

\begin{itemize}
\tightlist
\item
  \(\texttt{new\_transcript}() \to T\): Create a fresh transcript
  instance and absorb \(\texttt{suite\_id}\).
\item
  \(\texttt{absorb}(data \in \bold{\Sigma}^*)\): Feed bytes into the
  hash state. MUST NOT be called after squeeze.
\item
  \(\texttt{squeeze}(n \in \mathbb{N}) \to \bold{\Sigma}^n\): Produce
  \(n\) output bytes.
\item
  \(\texttt{fork}() \to T\): Clone the transcript state.
\end{itemize}

A concrete instantiation using SHA-512 is given in Appendix A.1.

\subsubsection{1.6.2. VRF Input}\label{vrf-input}

The VRF input point \(I \in \bold{G}\) is derived from the input
octet-string using a \(\texttt{hash\_to\_curve}\) function that maps
arbitrary-length octet-strings to points in \(\bold{G}\).

\[I \gets \texttt{hash\_to\_curve}(i)\]

The function MUST behave as a random oracle: its output must be
indistinguishable from a uniformly random point in \(\bold{G}\), and the
discrete logarithm of the output with respect to any known base must be
unknown.

Verifiers MUST independently compute each \(I_i\) from the corresponding
input octet-string using the procedure above. Accepting prover-supplied
input points without recomputation breaks the VRF security guarantees,
and in the case of Thin VRF (section 3), enables trivial forgery.

A concrete instantiation using Elligator 2 is given in Appendix A.2.

\subsubsection{1.6.3. VRF Output}\label{vrf-output}

The VRF output point is generated from the VRF input point and secret
key scalar:

\[O \gets x \cdot I\]

The VRF output hash is a fixed-length octet string derived from the
output point using a transcript-based point-to-hash procedure. The
procedure is deliberately independent of the proof scheme: for a given
key and input, the output point \(O = x \cdot I\) is unique regardless
of whether Tiny VRF, Thin VRF, or Pedersen VRF is used to prove
correctness. The scheme determines how the proof is constructed, not the
VRF output itself. This separation allows applications to obtain
consistent output hashes across schemes for the same underlying
evaluation.

\textbf{Input}:

\begin{itemize}
\tightlist
\item
  \(O \in \bold{G}\): VRF output point.
\item
  \(N \in \mathbb{N}\): Desired output length in bytes. MUST be fixed
  per application context; \(N\) is not absorbed into the transcript, so
  \(\texttt{squeeze}(N_1)\) is a prefix of \(\texttt{squeeze}(N_2)\) for
  \(N_1 < N_2\).
\end{itemize}

\textbf{Output}:

\begin{itemize}
\tightlist
\item
  \(o \in \bold{\Sigma}^N\): VRF output hash.
\end{itemize}

\textbf{Steps}:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \(T \gets \texttt{new\_transcript}()\)
\item
  \(T.\texttt{absorb}(\texttt{PointToHash} \;\Vert\; \texttt{enc\_point}(O))\)
\item
  \(o \gets T.\texttt{squeeze}(N)\)
\end{enumerate}

\textbf{Transcript}:

\begin{itemize}
\tightlist
\item
  \(T = \texttt{suite\_id} \;\Vert\; \texttt{PointToHash} \;\Vert\; \texttt{enc\_point}(O)\)
\end{itemize}

\subsubsection{1.6.4. Delinearization}\label{delinearization}

Merges input/output pairs into a single pair using delinearization
scalars derived from the transcript. For \(n = 0\), returns the identity
pair. For \(n = 1\), the pair is returned unchanged (\(z_0 = 1\)). For
\(n \geq 2\), random scalars prevent an attacker from mixing components
across pairs.

\textbf{Input}:

\begin{itemize}
\tightlist
\item
  \(\overline{io} \in (\bold{G}\times \bold{G})^n\): Sequence of
  input/output pairs.
\item
  \(T\): Transcript state.
\end{itemize}

\textbf{Output}:

\begin{itemize}
\tightlist
\item
  \((I_m, O_m) \in \bold{G}\times \bold{G}\): Merged input/output pair.
\end{itemize}

\textbf{Steps}:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  If \(n = 0\): return \((\mathcal{O}, \mathcal{O})\)
\item
  \(T.\texttt{absorb}(\texttt{Delinearize})\)
\item
  \(z_0 \gets 1\)
\item
  For \(i = 1, \ldots, n-1\):
  \(z_i \gets \texttt{dec\_scalar\_mod}(T.\texttt{squeeze}(\texttt{challenge\_len}))\)
\item
  \(I_m \gets \sum_{i=0}^{n-1} z_i \cdot I_i,\ O_m \gets \sum_{i=0}^{n-1} z_i \cdot O_i\)
\item
  Return \((I_m, O_m)\)
\end{enumerate}

\textbf{Transcript} (where \(T_{in}\) is the caller-supplied state):

\begin{itemize}
\tightlist
\item
  \(T = T_{in} \;\Vert\; \texttt{Delinearize}\)
\end{itemize}

\subsubsection{1.6.5. VRF Transcript}\label{vrf-transcript}

Shared transcript construction used by all VRF-AD schemes. Absorbs
input/output pairs, merges them via delinearization (section 1.6.4), and
absorbs additional data.

\textbf{Input}:

\begin{itemize}
\tightlist
\item
  \(scheme\): Scheme identifier tag.
\item
  \(\overline{io} \in (\bold{G}\times \bold{G})^n\): Sequence of
  input/output pairs.
\item
  \(ad \in \bold{\Sigma}^*\): Additional data octet-string.
\end{itemize}

\textbf{Output}:

\begin{itemize}
\tightlist
\item
  \(T\): Transcript state.
\item
  \((I_m, O_m) \in \bold{G}\times \bold{G}\): Merged input/output pair.
\end{itemize}

\textbf{Steps}:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \(T \gets \texttt{new\_transcript}()\)
\item
  \(T.\texttt{absorb}(scheme)\)
\item
  \(T.\texttt{absorb}(\texttt{enc\_64}(n))\)
\item
  For each \((I_i, O_i)\) in \(\overline{io}\):
  \(T.\texttt{absorb}(\texttt{enc\_point}(I_i) \;\Vert\; \texttt{enc\_point}(O_i))\)
\item
  \(T.\texttt{absorb}(\texttt{enc\_64}(\texttt{len}(ad)) \;\Vert\; ad)\)
\item
  \((I_m, O_m) \gets \texttt{delinearize}(\overline{io}, T.\texttt{fork}())\)
\item
  Return \((T, (I_m, O_m))\)
\end{enumerate}

\textbf{Transcript}:

\(\begin{aligned}
T = &\; \texttt{suite\_id} \;\Vert\; scheme \\
  &\; \Vert\; \texttt{enc\_64}(n) \;\Vert\; \texttt{enc\_point}(I_0) \;\Vert\; \texttt{enc\_point}(O_0) \;\Vert\; \cdots \;\Vert\; \texttt{enc\_point}(I_{n-1}) \;\Vert\; \texttt{enc\_point}(O_{n-1}) \\
  &\; \Vert\; \texttt{enc\_64}(\texttt{len}(ad)) \;\Vert\; ad
\end{aligned}\)

\subsubsection{1.6.6. Nonce}\label{nonce}

Deterministic nonce generation inspired by {[}RFC-8032{]} section 5.1.6.
The transcript carries shared state from \(\texttt{vrf\_transcript}\),
binding the nonce to the I/O pairs and additional data.

\textbf{Input}:

\begin{itemize}
\tightlist
\item
  \(d \in \bold{F}\): Secret scalar.
\item
  \(T\): Transcript state.
\end{itemize}

\textbf{Output}:

\begin{itemize}
\tightlist
\item
  \(k \in \bold{F}\): Nonce scalar.
\end{itemize}

\textbf{Steps}:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \(T' \gets T.\texttt{fork}()\)
\item
  \(T'.\texttt{absorb}(\texttt{NonceExpand} \;\Vert\; \texttt{enc\_scalar}(d))\)
\item
  \(h \gets T'.\texttt{squeeze}(64)\)
\item
  \(T.\texttt{absorb}(\texttt{Nonce} \;\Vert\; h)\)
\item
  \(k \gets \texttt{dec\_scalar\_mod}(T.\texttt{squeeze}(\text{expanded\_scalar\_len}))\)
\item
  If \(k = 0\): abort (implementation error; probability
  \(\approx 2^{-253}\)).
\end{enumerate}

\textbf{Transcript} (where \(T_{in}\) is the caller-supplied state):

\begin{itemize}
\tightlist
\item
  \(T' = T_{in} \;\Vert\; \texttt{NonceExpand} \;\Vert\; \texttt{enc\_scalar}(d)\)
\item
  \(T = T_{in} \;\Vert\; \texttt{Nonce} \;\Vert\; h\)
\end{itemize}

\subsubsection{1.6.7. Challenge}\label{challenge}

Derives a challenge scalar by absorbing curve points into the transcript
and squeezing.

\textbf{Input}:

\begin{itemize}
\tightlist
\item
  \(\bar{P} \in \bold{G}^m\): Sequence of \(m\) points.
\item
  \(T\): Transcript state.
\end{itemize}

\textbf{Output}:

\begin{itemize}
\tightlist
\item
  \(c \in \bold{F}\): Challenge scalar.
\end{itemize}

\textbf{Steps}:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \(T.\texttt{absorb}(\texttt{Challenge})\)
\item
  For each \(P_i\) in \(\bar{P}\):
  \(T.\texttt{absorb}(\texttt{enc\_point}(P_i))\)
\item
  \(c \gets \texttt{dec\_scalar\_mod}(T.\texttt{squeeze}(\texttt{challenge\_len}))\)
\end{enumerate}

\textbf{Transcript} (where \(T_{in}\) is the caller-supplied state):

\begin{itemize}
\tightlist
\item
  \(T = T_{in} \;\Vert\; \texttt{Challenge} \;\Vert\; \texttt{enc\_point}(P_0) \;\Vert\; \cdots \;\Vert\; \texttt{enc\_point}(P_{m-1})\)
\end{itemize}

\section{2. Tiny VRF}\label{tiny-vrf}

Compact VRF-AD scheme producing a short \((c, s)\) proof. Like Thin VRF,
it prepends the Schnorr pair \((G, Y)\) to the I/O list and proves a
single DLEQ on the delinearized merged pair. The challenge scalar \(c\)
is stored instead of the nonce commitment, yielding a smaller proof at
the cost of not supporting batch verification.

\textbf{Security}: VRF input points MUST be constructed via
hash-to-curve. If a prover knows \(d\) such that \(I = d \cdot G\), they
can forge arbitrary outputs for that input, because the delinearization
merges the Schnorr and VRF pairs into a single check that collapses when
all points are multiples of \(G\).

\textbf{Proof encoding}: The challenge \(c\) is produced by squeezing
\(\texttt{challenge\_len}\) bytes from the transcript. Since
\(2^{8 \cdot \texttt{challenge\_len}} < r\), no modular reduction occurs
and \(c\) is encoded as its raw \(\texttt{challenge\_len}\)-byte
little-endian representation. The scalar \(s\) is encoded via
\(\texttt{enc\_scalar}\) (32 bytes). The total proof size is
\(\texttt{challenge\_len} + 32\) bytes. Verifiers MUST reject proofs
where \(c \geq 2^{8 \cdot \texttt{challenge\_len}}\).

\subsection{2.1. Prove}\label{prove}

\textbf{Input}:

\begin{itemize}
\tightlist
\item
  \(x \in \bold{F}\): Secret key.
\item
  \(\overline{io} \in (\bold{G}\times \bold{G})^n\): VRF input/output
  pairs.
\item
  \(ad \in \bold{\Sigma}^*\): Additional data octet-string.
\end{itemize}

\textbf{Output}:

\begin{itemize}
\tightlist
\item
  \(\pi = (c, s) \in (\bold{F}, \bold{F})\): Schnorr-like proof.
\end{itemize}

\textbf{Steps}:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \(Y \gets x \cdot G\)
\item
  \((T, (I_m, O_m)) \gets \texttt{vrf\_transcript}(\texttt{TinyVrf}, [(G, Y)] \;\Vert\; \overline{io}, ad)\)
\item
  \(k \gets \texttt{nonce}(x, T.\texttt{fork}())\)
\item
  \(R \gets k \cdot I_m\)
\item
  \(c \gets \texttt{challenge}([R], T)\)
\item
  \(s \gets k + c \cdot x\)
\item
  \(\pi \gets (c, s)\)
\end{enumerate}

\subsection{2.2. Verify}\label{verify}

\textbf{Input}:

\begin{itemize}
\tightlist
\item
  \(Y \in \bold{G}\): Public key.
\item
  \(\overline{io} \in (\bold{G}\times \bold{G})^n\): VRF input/output
  pairs.
\item
  \(ad \in \bold{\Sigma}^*\): Additional data octet-string.
\item
  \(\pi = (c, s) \in (\bold{F}, \bold{F})\): Schnorr-like proof.
\end{itemize}

\textbf{Output}:

\begin{itemize}
\tightlist
\item
  \(\theta \in \{ \top, \bot \}\): \(\top\) if proof is valid, \(\bot\)
  otherwise.
\end{itemize}

\textbf{Steps}:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Validate \(Y\) and all \(I_i, O_i\)
  \(\in \bold{G}\setminus \{\mathcal{O}\}\), output \(\bot\) if any is
  invalid or the identity.
\item
  \((T, (I_m, O_m)) \gets \texttt{vrf\_transcript}(\texttt{TinyVrf}, [(G, Y)] \;\Vert\; \overline{io}, ad)\)
\item
  \(R \gets s \cdot I_m - c \cdot O_m\)
\item
  \(c' \gets \texttt{challenge}([R], T)\)
\item
  \(\theta \gets \top \text{ if } c = c' \text{ else } \bot\)
\end{enumerate}

\section{3. Thin VRF}\label{thin-vrf}

Thin VRF is structurally similar to Tiny VRF: it prepends \((G, Y)\) to
the I/O pairs, applies delinearization, and proves a single DLEQ on the
merged pair. The difference is the proof format: Thin VRF stores the
nonce commitment \(R\) rather than the challenge \(c\), which enables
batch verification at the cost of a slightly larger proof.

\subsection{3.1. Prove}\label{prove-1}

\textbf{Input}:

\begin{itemize}
\tightlist
\item
  \(x \in \bold{F}\): Secret key.
\item
  \(\overline{io} \in (\bold{G}\times \bold{G})^n\): VRF input/output
  pairs.
\item
  \(ad \in \bold{\Sigma}^*\): Additional data octet-string.
\end{itemize}

\textbf{Output}:

\begin{itemize}
\tightlist
\item
  \(\pi = (R, s) \in (\bold{G}, \bold{F})\): Thin VRF proof.
\end{itemize}

\textbf{Steps}:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \(Y \gets x \cdot G\)
\item
  \((T, (I_m, O_m)) \gets \texttt{vrf\_transcript}(\texttt{ThinVrf}, [(G, Y)] \;\Vert\; \overline{io}, ad)\)
\item
  \(k \gets \texttt{nonce}(x, T.\texttt{fork}())\)
\item
  \(R \gets k \cdot I_m\)
\item
  \(c \gets \texttt{challenge}([R], T)\)
\item
  \(s \gets k + c \cdot x\)
\item
  \(\pi \gets (R, s)\)
\end{enumerate}

\subsection{3.2. Verify}\label{verify-1}

\textbf{Input}:

\begin{itemize}
\tightlist
\item
  \(Y \in \bold{G}\): Public key.
\item
  \(\overline{io} \in (\bold{G}\times \bold{G})^n\): VRF input/output
  pairs.
\item
  \(ad \in \bold{\Sigma}^*\): Additional data octet-string.
\item
  \(\pi = (R, s) \in (\bold{G}, \bold{F})\): Thin VRF proof.
\end{itemize}

\textbf{Output}:

\begin{itemize}
\tightlist
\item
  \(\theta \in \{ \top, \bot \}\): \(\top\) if proof is valid, \(\bot\)
  otherwise.
\end{itemize}

\textbf{Steps}:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Validate \(R \in \bold{G}\) and
  \(Y, I_i, O_i \in \bold{G}\setminus \{\mathcal{O}\}\) for all \(i\),
  output \(\bot\) if any point is not in \(\bold{G}\), or if \(Y\) or
  any \(I_i, O_i\) is the identity.
\item
  \((T, (I_m, O_m)) \gets \texttt{vrf\_transcript}(\texttt{ThinVrf}, [(G, Y)] \;\Vert\; \overline{io}, ad)\)
\item
  \(c \gets \texttt{challenge}([R], T)\)
\item
  \(\theta \gets \top \text{ if } s \cdot I_m = R + c \cdot O_m \text{ else } \bot\)
\end{enumerate}

The identity is a legal value for \(R\) and MUST NOT be rejected. \(R\)
is a prover-chosen commitment and step 4 is sound for any value of it.
\(R\) is the identity only when \(k = 0\), which makes \(s = c \cdot x\)
and publishes the secret key. A verifier that rejects it diverges from
one that does not, on a proof that no honest prover produces.

\subsection{3.3. Batch Verify}\label{batch-verify}

Multiple Thin VRF proofs can be verified together by combining the
individual verification equations with random weights (Schwartz-Zippel
lemma).

\textbf{Input}:

\begin{itemize}
\tightlist
\item
  For \(j = 0, \ldots, N-1\): a tuple
  \((Y_j, \overline{io}_j, ad_j, \pi_j)\) where:

  \begin{itemize}
  \tightlist
  \item
    \(Y_j \in \bold{G}\): Public key.
  \item
    \(\overline{io}_j \in (\bold{G}\times \bold{G})^{M_j}\): VRF
    input/output pairs.
  \item
    \(ad_j \in \bold{\Sigma}^*\): Additional data octet-string.
  \item
    \(\pi_j = (R_j, s_j) \in (\bold{G}, \bold{F})\): Thin VRF proof.
  \end{itemize}
\end{itemize}

\textbf{Output}:

\begin{itemize}
\tightlist
\item
  \(\theta \in \{ \top, \bot \}\): \(\top\) if all proofs verify,
  \(\bot\) otherwise.
\end{itemize}

\textbf{Steps}:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  For each proof \(j\):

  \begin{enumerate}
  \def\labelenumii{\alph{enumii}.}
  \tightlist
  \item
    Validate \(R_j \in \bold{G}\) and
    \(Y_j, I_{j,i}, O_{j,i} \in \bold{G}\setminus \{\mathcal{O}\}\) for
    all \(i\), output \(\bot\) if any point is not in \(\bold{G}\), or
    if \(Y_j\) or any \(I_{j,i}, O_{j,i}\) is the identity.
  \item
    \((T_j, (I_{m,j}, O_{m,j})) \gets \texttt{vrf\_transcript}(\texttt{ThinVrf}, [(G, Y_j)] \;\Vert\; \overline{io}_j, ad_j)\)
  \item
    \(c_j \gets \texttt{challenge}([R_j], T_j)\)
  \end{enumerate}
\item
  Derive random weights:

  \begin{enumerate}
  \def\labelenumii{\alph{enumii}.}
  \tightlist
  \item
    \(T_w \gets \texttt{new\_transcript}()\)
  \item
    \(T_w.\texttt{absorb}(\texttt{BatchVerify})\)
  \item
    For each \(j\):
    \(T_w.\texttt{absorb}(\texttt{enc\_scalar}(c_j) \;\Vert\; \texttt{enc\_scalar}(s_j))\)
  \end{enumerate}
\item
  Check the combined equation:
  \[\sum_{j=0}^{N-1} w_j \cdot (s_j \cdot I_{m,j} - R_j - c_j \cdot O_{m,j}) = \mathcal{O}\]
  where
  \(w_j \gets \texttt{dec\_scalar\_mod}(T_w.\texttt{squeeze}(\texttt{challenge\_len}))\).
\end{enumerate}

\textbf{Transcript}:

\(\begin{aligned}
T_w = &\; \texttt{suite\_id} \;\Vert\; \texttt{BatchVerify} \\
  &\; \Vert\; \texttt{enc\_scalar}(c_0) \;\Vert\; \texttt{enc\_scalar}(s_0) \;\Vert\; \cdots \;\Vert\; \texttt{enc\_scalar}(c_{N-1}) \;\Vert\; \texttt{enc\_scalar}(s_{N-1})
\end{aligned}\)

\section{4. Pedersen VRF}\label{pedersen-vrf}

Pedersen VRF resembles Tiny VRF but replaces the public key with a
Pedersen commitment to the secret key, which makes this VRF useful in
anonymized ring proofs.

The scheme proves that the output has been generated with a secret key
associated with a blinded public key (instead of the public key). The
blinded public key is a cryptographic commitment to the public key, and
it can be unblinded to prove that the output of the VRF corresponds to
the public key of the signer.

This specification mostly follows the design proposed by
\href{https://eprint.iacr.org/2023/002}{BCHSV23} {[}2{]} in section 4
with some details about blinding base point value and challenge
generation procedure.

The \emph{blinding base} \(B \in \bold{G}\) is defined as:
\[\footnotesize\begin{aligned}
x &= 23335687741101763108036518445642207119627658113885888016488710494487028845889 \\
y &= 5552214580375038693022409684979828600325210968745774080859660443337357929963
\end{aligned}\]

A point with unknown discrete logarithm derived using the
\texttt{hash\_to\_curve} function as described in Appendix A.2 with
input the string: \texttt{"pedersen-blinding"}.

\subsection{4.1. Prove}\label{prove-2}

\textbf{Input}:

\begin{itemize}
\tightlist
\item
  \(x \in \bold{F}\): Secret key.
\item
  \(\overline{io} \in (\bold{G}\times \bold{G})^n\): VRF input/output
  pairs.
\item
  \(ad \in \bold{\Sigma}^*\): Additional data octet-string.
\end{itemize}

\textbf{Output}:

\begin{itemize}
\tightlist
\item
  \(\pi = (\bar{Y}, R, O_k, s, s_b) \in (\bold{G}, \bold{G}, \bold{G}, \bold{F}, \bold{F})\):
  Pedersen proof.
\item
  \(b \in \bold{F}\): Blinding factor.
\end{itemize}

\textbf{Steps}:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \((T, (I_m, O_m)) \gets \texttt{vrf\_transcript}(\texttt{PedersenVrf}, \overline{io}, ad)\)
\item
  \(b \gets \texttt{blinding}(x, T.\texttt{fork}())\) (see Appendix A.4)
\item
  \(\bar{Y} \gets x \cdot G + b \cdot B\)
\item
  \(T.\texttt{absorb}(\texttt{enc\_point}(\bar{Y}))\)
\item
  \(k \gets \texttt{nonce}(x, T.\texttt{fork}())\),
  \(\quad k_b \gets \texttt{nonce}(b, T.\texttt{fork}())\)
\item
  \(R \gets k \cdot G + k_b \cdot B\)
\item
  \(O_k \gets k \cdot I_m\)
\item
  \(c \gets \texttt{challenge}([R, O_k], T)\)
\item
  \(s \gets k + c \cdot x\), \(\quad s_b \gets k_b + c \cdot b\)
\item
  \(\pi \gets (\bar{Y}, R, O_k, s, s_b)\)
\end{enumerate}

\subsection{4.2. Verify}\label{verify-2}

\textbf{Input}:

\begin{itemize}
\tightlist
\item
  \(\overline{io} \in (\bold{G}\times \bold{G})^n\): VRF input/output
  pairs.
\item
  \(ad \in \bold{\Sigma}^*\): Additional data octet-string.
\item
  \(\pi = (\bar{Y}, R, O_k, s, s_b) \in (\bold{G}, \bold{G}, \bold{G}, \bold{F}, \bold{F})\):
  Pedersen proof.
\end{itemize}

\textbf{Output}:

\begin{itemize}
\tightlist
\item
  \(\theta \in \{ \top, \bot \}\): \(\top\) if proof is valid, \(\bot\)
  otherwise.
\end{itemize}

\textbf{Steps}:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Validate \(R, O_k \in \bold{G}\) and
  \(\bar{Y}, I_i, O_i \in \bold{G}\setminus \{\mathcal{O}\}\) for all
  \(i\), output \(\bot\) if any point is not in \(\bold{G}\), or if
  \(\bar{Y}\) or any \(I_i, O_i\) is the identity.
\item
  \((T, (I_m, O_m)) \gets \texttt{vrf\_transcript}(\texttt{PedersenVrf}, \overline{io}, ad)\)
\item
  \(T.\texttt{absorb}(\texttt{enc\_point}(\bar{Y}))\)
\item
  \(c \gets \texttt{challenge}([R, O_k], T)\)
\item
  \(\theta_0 \gets \top \text{ if } O_k + c \cdot O_m = s \cdot I_m \text{ else } \bot\)
\item
  \(\theta_1 \gets \top \text{ if } R + c \cdot \bar{Y} = s \cdot G + s_b \cdot B \text{ else } \bot\)
\item
  \(\theta = \theta_0 \land \theta_1\)
\end{enumerate}

Note: no public key appears in the verify inputs -- verification uses
the committed key \(\bar{Y}\) from the proof.

The identity is a legal value for \(R\) and \(O_k\) and MUST NOT be
rejected. Both are prover-chosen commitments and steps 5 and 6 are sound
for any value of them. Both are the identity only when \(k = 0\), which
makes \(s = c \cdot x\) and publishes the secret key. \(O_k\) is also
the identity for every honest proof with \(n = 0\), where
\(I_m = \mathcal{O}\) (see Appendix B). A verifier that rejects these
values diverges from one that does not.

\subsection{4.3. Unblinding}\label{unblinding}

Links a Pedersen VRF proof to a specific public key. The prover reveals
the blinding factor \(b\), and the verifier checks that the proof is
valid and that its committed key opens to the claimed public key.

\textbf{Input}:

\begin{itemize}
\tightlist
\item
  \(\overline{io} \in (\bold{G}\times \bold{G})^n\): VRF input/output
  pairs.
\item
  \(ad \in \bold{\Sigma}^*\): Additional data octet-string.
\item
  \(\pi = (\bar{Y}, R, O_k, s, s_b) \in (\bold{G}, \bold{G}, \bold{G}, \bold{F}, \bold{F})\):
  Pedersen proof.
\item
  \(b \in \bold{F}\): Blinding factor revealed by the prover.
\item
  \(Y \in \bold{G}\): Claimed public key.
\end{itemize}

\textbf{Output}:

\begin{itemize}
\tightlist
\item
  \(\theta \in \{ \top, \bot \}\): \(\top\) if the proof is attributable
  to \(Y\), \(\bot\) otherwise.
\end{itemize}

\textbf{Steps}:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Validate \(Y\) and \(\bar{Y}\)
  \(\in \bold{G}\setminus \{\mathcal{O}\}\), output \(\bot\) if either
  is invalid or the identity.
\item
  \(\theta_0 \gets Pedersen.verify(\overline{io}, ad, \pi)\) (section
  4.2)
\item
  \(\theta_1 \gets \top \text{ if } \bar{Y} = Y + b \cdot B \text{ else } \bot\)
\item
  \(\theta \gets \theta_0 \land \theta_1\)
\end{enumerate}

The verifier MUST NOT accept the association unless step 2 outputs
\(\top\) for the same \((\overline{io}, ad, \pi)\) that supplied
\(\bar{Y}\). Step 3 on its own is not evidence of authorship: any party
can compute \(\bar{Y} = Y + b \cdot B\) for a public key \(Y\) it does
not control, without knowledge of the corresponding secret key.

\subsection{4.4. Batch Verify}\label{batch-verify-1}

Multiple Pedersen VRF proofs can be verified together by combining the
individual verification equations with random weights (Schwartz-Zippel
lemma). Each proof contributes two equations (VRF correctness and
Pedersen commitment correctness), each weighted by an independent random
scalar.

\textbf{Input}:

\begin{itemize}
\tightlist
\item
  For \(j = 0, \ldots, N-1\): a tuple \((\overline{io}_j, ad_j, \pi_j)\)
  where:

  \begin{itemize}
  \tightlist
  \item
    \(\overline{io}_j \in (\bold{G}\times \bold{G})^{M_j}\): VRF
    input/output pairs.
  \item
    \(ad_j \in \bold{\Sigma}^*\): Additional data octet-string.
  \item
    \(\pi_j = (\bar{Y}_j, R_j, O_{k,j}, s_j, s_{b,j}) \in (\bold{G}, \bold{G}, \bold{G}, \bold{F}, \bold{F})\):
    Pedersen proof.
  \end{itemize}
\end{itemize}

\textbf{Output}:

\begin{itemize}
\tightlist
\item
  \(\theta \in \{ \top, \bot \}\): \(\top\) if all proofs verify,
  \(\bot\) otherwise.
\end{itemize}

\textbf{Steps}:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  For each proof \(j\):

  \begin{enumerate}
  \def\labelenumii{\alph{enumii}.}
  \tightlist
  \item
    Validate \(R_j, O_{k,j} \in \bold{G}\) and
    \(\bar{Y}_j, I_{j,i}, O_{j,i} \in \bold{G}\setminus \{\mathcal{O}\}\)
    for all \(i\), output \(\bot\) if any point is not in \(\bold{G}\),
    or if \(\bar{Y}_j\) or any \(I_{j,i}, O_{j,i}\) is the identity.
  \item
    \((T_j, (I_{m,j}, O_{m,j})) \gets \texttt{vrf\_transcript}(\texttt{PedersenVrf}, \overline{io}_j, ad_j)\)
  \item
    \(T_j.\texttt{absorb}(\texttt{enc\_point}(\bar{Y}_j))\)
  \item
    \(c_j \gets \texttt{challenge}([R_j, O_{k,j}], T_j)\)
  \end{enumerate}
\item
  Derive random weights:

  \begin{enumerate}
  \def\labelenumii{\alph{enumii}.}
  \tightlist
  \item
    \(T_w \gets \texttt{new\_transcript}()\)
  \item
    \(T_w.\texttt{absorb}(\texttt{BatchVerify})\)
  \item
    For each \(j\):
    \(T_w.\texttt{absorb}(\texttt{enc\_scalar}(c_j) \;\Vert\; \texttt{enc\_scalar}(s_j) \;\Vert\; \texttt{enc\_scalar}(s_{b,j}))\)
  \end{enumerate}
\item
  Check the combined equations:
  \[\sum_{j=0}^{N-1} t_j \cdot (O_{k,j} + c_j \cdot O_{m,j} - s_j \cdot I_{m,j}) + u_j \cdot (R_j + c_j \cdot \bar{Y}_j - s_j \cdot G - s_{b,j} \cdot B) = \mathcal{O}\]
  where:

  \begin{itemize}
  \tightlist
  \item
    \(t_j \gets \texttt{dec\_scalar\_mod}(T_w.\texttt{squeeze}(\texttt{challenge\_len}))\)
  \item
    \(u_j \gets \texttt{dec\_scalar\_mod}(T_w.\texttt{squeeze}(\texttt{challenge\_len}))\)
  \end{itemize}
\end{enumerate}

\textbf{Transcript}:

\(\begin{aligned}
T_w = &\; \texttt{suite\_id} \;\Vert\; \texttt{BatchVerify} \\
  &\; \Vert\; \texttt{enc\_scalar}(c_0) \;\Vert\; \texttt{enc\_scalar}(s_0) \;\Vert\; \texttt{enc\_scalar}(s_{b,0}) \\
  &\; \Vert\; \cdots \\
  &\; \Vert\; \texttt{enc\_scalar}(c_{N-1}) \;\Vert\; \texttt{enc\_scalar}(s_{N-1}) \;\Vert\; \texttt{enc\_scalar}(s_{b,N-1})
\end{aligned}\)

\section{5. Ring VRF}\label{ring-vrf}

Anonymized ring VRF based on Pedersen VRF (section 4) and Ring Proof as
proposed in \href{https://eprint.iacr.org/2023/002}{BCHSV23} {[}2{]}.

The ring proof can be seen as a special case of the Committee Key Scheme
(CKS) introduced by \href{https://eprint.iacr.org/2022/1205}{CSSV22}
{[}3{]}, reduced to a single signer. In CKS, a prover commits to a set
of public keys using a KZG polynomial commitment and produces a SNARK
showing that a subset of keys -- identified by a bitvector -- belongs to
the committed set. The ring proof is the degenerate case where the
bitvector has exactly one bit set: it proves that a single (blinded) key
is a member of the committed ring, without revealing which one.

The concrete specification of the ring proof scheme is given in
\href{https://github.com/davxy/ring-proof-spec}{VG24} {[}5{]}. The
following configuration specializes it for this scheme:

  \item

  \end{itemize}
\item
  Accumulator base point \(S \in \bold{G}\) is defined as:

\subsection{5.2. Verify}\label{verify-3}

\textbf{Input}:

\begin{itemize}
\tightlist
\item
  \(\overline{io} \in (\bold{G}\times \bold{G})^n\): VRF input/output
  pairs.
\item
  \(ad \in \bold{\Sigma}^*\): Additional data octet-string.
\item
  \(\pi_p \in (\bold{G}, \bold{G}, \bold{G}, \bold{F}, \bold{F})\):
  Pedersen proof.
\item
  \(\pi_r \in ((G_1)^4, (\bold{F})^7, G_1, \bold{F}, G_1, G_1)\): Ring
  proof.
\item
  \(V \in (G_1)^3\): Ring verifier (pre-processed commitment).
\end{itemize}

\textbf{Output}:

\begin{itemize}
\tightlist
\item
  \(\theta \in \{ \top, \bot \}\): \(\top\) if proof is valid, \(\bot\)
  otherwise.
\end{itemize}

\textbf{Steps}:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \(\theta_0 \gets Pedersen.verify(\overline{io}, ad, \pi_p)\)
\item
  \((\bar{Y}, R, O_k, s, s_b) \gets \pi_p\)
\item
  \(\theta_1 \gets Ring.verify(V, \pi_r, \bar{Y})\)
\item
  \(\theta \gets \theta_0 \land \theta_1\)
\end{enumerate}

Note: to attribute a ring signature to a public key, apply the
unblinding procedure of section 4.3 to \(\pi_p\). The verifier MUST NOT
accept that attribution unless this procedure outputs \(\top\) for the
same inputs, because \(Ring.verify\) is what binds \(\bar{Y}\) to a
member of the ring. A \(\top\) from \(Pedersen.verify\) alone proves
knowledge of an opening of \(\bar{Y}\), not ring membership.

\section{Appendix A. Concrete
Instantiations}\label{appendix-a.-concrete-instantiations}

The following are concrete instantiations of the abstract interfaces
defined in the main specification. They are provided to enable
interoperable implementations and reproducible test vectors. Alternative
constructions that satisfy the same security requirements are equally
valid.

\subsection{A.1. Transcript
Construction}\label{a.1.-transcript-construction}

Instantiation of the transcript interface (section 1.6.1) using SHA-512.

\textbf{Initialization}: \(\texttt{new\_transcript}()\) creates a fresh
SHA-512 state and feeds \(\texttt{suite\_id}\) into it.

\textbf{Absorb}: feeds raw bytes directly into the SHA-512 state.
Consecutive absorb calls are equivalent to a single absorb of the
concatenated data. This is safe because all protocol fields use
fixed-width encoding (\(\texttt{enc\_point}\): 32 bytes,
\(\texttt{enc\_scalar}\): 32 bytes, \(\texttt{enc\_64}\): 8 bytes,
domain tags: 1 byte) or explicit length prefixing (\(ad\) via
\(\texttt{enc\_64}(\texttt{len}(ad)) \;\Vert\; ad\)), so the byte stream
is unambiguous given the inputs agreed upon by both parties.

\textbf{Squeeze} (counter-mode XOF): on the first squeeze call, finalize
the SHA-512 state to obtain a 64-byte \(seed\). Then produce output
blocks:

\[block_i = \text{SHA-512}(seed \;\Vert\; \texttt{enc\_64}(i)) \quad \text{for } i = 0, 1, 2, \ldots\]

where \(\texttt{enc\_64}(n)\) encodes integer \(n\) as an 8-byte
little-endian octet string. Each block yields 64 bytes. Output is read
sequentially across blocks; partial block state is preserved between
squeeze calls.

\textbf{Fork}: duplicates the full internal state (including any partial
block position if squeezing has begun).

\subsection{A.2. Hash to Curve}\label{a.2.-hash-to-curve}

Instantiation of the \(\texttt{hash\_to\_curve}\) function (section
1.6.2) using the method defined in section 3 of
\href{https://datatracker.ietf.org/doc/rfc9380}{RFC-9380} {[}6{]}, with
the \emph{Elligator 2} map to curve (section 6.8.2) and
\(\texttt{expand\_message\_xmd}\) with SHA-512 (section 5.3.1).

With one difference from section 5.3.1: the zero prefix \(Z_{pad}\) of
\(\texttt{expand\_message\_xmd}\) has \(L = 48\) octets, the expanded
length of one field element
\(\lceil(\lceil\log_2(p)\rceil + 128) / 8\rceil\), and not
\(s_{in\_bytes} = 128\), the SHA-512 input block size. The expansion
length is \(2 \cdot L = 96\) octets. An implementation with the RFC
prefix does not reproduce the constants of this document or the vectors
of Appendix C.

This is the random oracle (\texttt{\_RO\_}) construction: the input is
hashed to two independent field elements, each is mapped to a curve
point via Elligator 2, and the results are added.

\[I \gets \texttt{hash\_to\_curve\_ell2}(DST, i)\]

The domain separation tag is:

\[DST = \texttt{suite\_id} \;\Vert\; \texttt{HashToCurve}\]

i.e.~the 27-byte \(\texttt{suite\_id}\) string concatenated with the
single \(\texttt{HashToCurve}\) tag byte (0x60). This matches the
per-operation tagging used elsewhere in the protocol.

\subsection{A.3. Secret Key
Generation}\label{a.3.-secret-key-generation}

Derives a secret scalar from a 32-byte seed.

\textbf{Input}:

\begin{itemize}
\tightlist
\item
  \(seed \in \bold{\Sigma}^{32}\): seed octet-string.
\end{itemize}

\textbf{Output}:

\begin{itemize}
\tightlist
\item
  \(x \in \bold{F}\): secret key scalar.
\end{itemize}

\textbf{Steps}:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \(i \gets 0\)
\item
  \(T \gets \texttt{new\_transcript}()\)
\item
  \(T.\texttt{absorb}(seed)\)
\item
  If \(i > 0\): \(T.\texttt{absorb}(i)\) where \(i\) is encoded as a
  single octet
\item
  \(d \gets \texttt{dec\_scalar\_mod}(seed)\)
\item
  \(x \gets \texttt{nonce}(d, T)\)
\item
  If \(x = 0\): increment \(i\) and go to step 2
\item
  Return \(x\)
\end{enumerate}

The seed is absorbed into the transcript and also passed as a scalar to
the \(\texttt{nonce}\) procedure (section 1.6.6), ensuring seed entropy
flows through both the transcript state and the secret scalar input
paths.

\subsection{A.4. Blinding Factor
Generation}\label{a.4.-blinding-factor-generation}

Generates the Pedersen VRF blinding factor deterministically from the
secret key and the VRF transcript state, using the nonce function
(section 1.6.6) with a distinct domain separator.

\textbf{Linkability warning}: because \(b\) is derived deterministically
from \((x, T)\), two Pedersen VRF proofs with the same secret key, I/O
pairs, and additional data will produce the same blinding factor \(b\)
and therefore the same blinded public key
\(\bar{Y} = x \cdot G + b \cdot B\). An observer can detect that both
proofs originate from the same signer by comparing \(\bar{Y}\) values.
Applications that require unlinkability across repeated proofs on the
same inputs should generate \(b\) as a fresh uniformly random scalar
rather than using this deterministic method.

\textbf{Input}:

\begin{itemize}
\tightlist
\item
  \(x \in \bold{F}\): Secret scalar.
\item
  \(T\): Transcript state (from \(\texttt{vrf\_transcript}\)).
\end{itemize}

\textbf{Output}:

\begin{itemize}
\tightlist
\item
  \(b \in \bold{F}\): Blinding factor scalar.
\end{itemize}

\textbf{Steps}:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \(T.\texttt{absorb}(\texttt{PedersenBlinding})\)
\item
  \(b \gets \texttt{nonce}(x, T)\)
\end{enumerate}

\section{Appendix B. Behavior with Zero I/O
Pairs}\label{appendix-b.-behavior-with-zero-io-pairs}

When \(n = 0\) no VRF output can be derived, since there are no output
points to hash. The proof-of-knowledge component, however, remains sound
in all schemes: a valid proof still requires knowledge of the secret key
\(x\).

\begin{itemize}
\item
  \textbf{Tiny VRF and Thin VRF}: Both schemes prepend the Schnorr pair
  \((G, Y)\) to the I/O list before delinearization (sections 2.1 and
  3.1, step 2), so the internal pair count is at least 1 regardless of
  the user-supplied \(n\). With zero VRF pairs, the scheme degenerates
  to a Schnorr signature on the additional data \(ad\), proving
  knowledge of \(x\) for public key \(Y\).
\item
  \textbf{Pedersen VRF}: No Schnorr pair is prepended, so with \(n = 0\)
  the \(\texttt{delinearize}\) procedure (section 1.6.4) sets the merged
  pair to the identity: \((I_m, O_m) = (\mathcal{O}, \mathcal{O})\). The
  VRF output check \(O_k + c \cdot O_m = s \cdot I_m\) degenerates to
  \(O_k = \mathcal{O}\), which an honest prover satisfies because
  \(O_k = k \cdot \mathcal{O}\). This is why section 4.2 step 1 accepts
  the identity for \(O_k\). The commitment check
  \(R + c \cdot \bar{Y} = s \cdot G + s_b \cdot B\) still proves
  knowledge of the Pedersen commitment opening \((x, b)\).
\end{itemize}

Such a proof carries no VRF output. An application that consumes a VRF
output MUST require \(n \geq 1\) at the call site. The schemes do not
enforce it.

\subsection{C.4. Ring VRF Test
Vectors}\label{c.4.-ring-vrf-test-vectors}

KZG SRS parameters are derived from Zcash BLS12-381
\href{https://zfnd.org/conclusion-of-the-powers-of-tau-ceremony}{powers
of tau ceremony}.

The ring has 8 public keys. The vectors use the domain of section 5,
\(|\mathbb{D}| = 2048\), with the generator \(\omega\) of section 5.
This domain holds 1791 keys. The padding point \(\square\) fills the key
positions after the 8 ring keys.

The ring commitment and the ring proof depend on \(|\mathbb{D}|\). With
the smallest domain for 8 keys, \(|\mathbb{D}| = 512\), an
implementation does not reproduce \texttt{ring\_pks\_com} and
\texttt{ring\_proof}.

The evaluations for the ZK domain items, specifically the evaluations of
the last three items in the evaluation domain \(\mathbb{D}\), are set to
0 rather than being randomly generated.

\begin{verbatim}

\end{verbatim}
